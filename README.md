# react-telemetry-open

React-aware, vendor-neutral observability for React 18+ applications.

Zero boilerplate. OTLP output. No vendor lock-in.

[![npm version](https://img.shields.io/npm/v/react-telemetry-open)](https://npmjs.com/package/react-telemetry-open)
[![License](https://img.shields.io/badge/license-Apache%202.0-blue)](./LICENSE)

---

## Why react-telemetry-open

Existing observability tools operate below the React layer:

- **Error tracking tools** are purpose-built for exception capture — render performance, concurrent mode timing, and component attribution are outside their design scope
- **Real User Monitoring (RUM) tools** measure browser-level metrics — React-specific signals like unnecessary re-renders and component-level attribution emerge at a layer above what standard RUM instruments
- **Raw OpenTelemetry** requires significant manual instrumentation to produce React-aware signals
- **Development-only render profilers** produce no production observability data

react-telemetry-open fills this gap. It tracks signals that only exist inside React — unnecessary re-renders, component-attributed long tasks, rage clicks, ErrorBoundary catches — and exports them in standard OTLP format. One package. Any backend. Zero configuration to start.

---

## What it tracks

**React signals** — render count and timing, rage clicks, time to first interaction

**Standard signals** — Core Web Vitals (FCP/LCP/FID/CLS/INP), JS errors, unhandled rejections, React ErrorBoundary catches, network timing, JavaScript heap memory, long tasks, resource load times

**Context on every event** — component name, route, session ID, device type, browser, OS, connection quality, React version

## Quick start

```bash
npm install react-telemetry-open
npx react-telemetry-open init
```

Wrap your app:

```tsx
import { TelemetryProvider } from 'react-telemetry-open'
import appConfig from '../telemetry.config.json'

function App() {
  return (
    <TelemetryProvider appConfig={appConfig}>
      <Router>
        <YourApp />
      </Router>
    </TelemetryProvider>
  )
}
```

Open DevTools. See telemetry in the console. Done.

---

## Props

**`appConfig`** — static application identity. Import your `telemetry.config.json` here.
Generated by `npx react-telemetry-open init`. Contains app name, version, environment, exporter.

**`config`** — runtime overrides. Values known only at runtime — sampling rate based on device
speed, signals based on user consent, debug flag based on environment.

```tsx
<TelemetryProvider
  appConfig={appConfig}
  config={{
    sampling: { rate: isSlowDevice ? 0.1 : 1.0 },
    signals: { memory: hasUserConsented },
  }}
>
```

Both props are optional. Without either, defaults are used and debug warnings appear
telling you exactly what to set up.

---

## Zero config

Works immediately with no configuration file. Defaults:

- Exporter: console (data prints to DevTools)
- All signals: enabled
- Sampling: 100%

Without running `npx react-telemetry-open init`, app name and version show as
`unknown-app` and `0.0.0` in telemetry events. The CLI reads your `package.json`
and creates `telemetry.config.json` with the correct values — this is why it is
the recommended first step after install.

## Track interactions

```tsx
import { useTrackInteraction } from 'react-telemetry-open'

function CheckoutButton() {
  const { onClick } = useTrackInteraction('checkout-submit')
  return <button onClick={onClick}>Buy Now</button>
}
```

---

## Track custom events

```tsx
import { useTrackEvent } from 'react-telemetry-open'

function OnboardingFlow() {
  const track = useTrackEvent()

  const handleComplete = () => {
    track('onboarding:completed', { step: 4, plan: 'pro' })
  }
}
```

## Production setup

Run the CLI to generate both development and production config files:

```bash
npx react-telemetry-open init
```

This creates `telemetry.config.json` (development) and `telemetry.config.prod.json` (production).

Edit `telemetry.config.prod.json` with your production values:

```json
{
  "app": {
    "environment": "production",
    "buildId": "$VITE_BUILD_ID"
  },
  "exporter": {
    "type": "otlp",
    "url": "$VITE_OTEL_URL",
    "apiKey": "$VITE_OTEL_KEY"
  },
  "sampling": {
    "rate": 0.1
  },
  "debug": false
}
```

Import the correct config based on environment and pass as `appConfig`:

```tsx
import appConfig from '../telemetry.config.json'
import prodConfig from '../telemetry.config.prod.json'

const config = import.meta.env.PROD ? prodConfig : appConfig

<TelemetryProvider appConfig={config}>
  <App />
</TelemetryProvider>
```

Set `$VITE_OTEL_URL` and `$VITE_OTEL_KEY` in your `.env.production` file.
Data flows to any OTel-compatible backend.

## Backend compatibility

react-telemetry-open sends standard OTLP/HTTP — works with any OTel-compatible backend.

| Backend | Direct from browser | Notes |
|---|---|---|
| Self-hosted OTel Collector | ✅ | Configure CORS on your collector |
| Grafana Alloy (self-hosted) | ✅ | Configure CORS in alloy.config |
| Honeycomb | ✅ | Works directly |
| Axiom | ✅ | Works directly |
| Grafana Cloud | ⚠️ | Requires a proxy — see below |
| Any OTLP/HTTP endpoint | ✅ | As long as CORS headers are present |

### Grafana Cloud and CORS

Grafana Cloud's OTLP gateway does not support browser CORS — it is designed
for server-to-server communication. A lightweight proxy is required between
your app and Grafana Cloud:

```
Browser → your proxy (CORS enabled) → Grafana Cloud
```

The simplest proxy is a single Vercel or Netlify serverless function that
forwards requests with your Grafana credentials server-side. This keeps
your API key off the client entirely.

For self-hosted OTel Collector or Grafana Alloy, direct browser connections
work — configure `cors.allowed_origins` in your collector to include your
app's domain.

## Privacy

react-telemetry-open is designed with privacy in mind:

- **Anonymous sessions** — session IDs are random UUIDs, not linked to any user identity
- **URL sanitisation** — query parameters stripped by default; numeric IDs and UUIDs in paths replaced with `:id` and `:uuid`
- **No raw user agent** — the user agent string is never transmitted; only parsed structured fields (browser name, version, OS)
- **No input values** — interaction tracking records that an event occurred, never what was typed
- **Do Not Track** — browser DNT setting is honoured by default; all collection skipped when enabled
- **configurable** — all privacy defaults are configurable per your requirements

**Custom event properties are developer-controlled.** Do not pass personally identifiable information (names, emails, user IDs, IP addresses) as custom event properties. Use anonymised identifiers instead.

## Secrets

API keys and Collector URLs must never be hardcoded in config files.
Always use `$VAR_NAME` syntax which resolves from environment variables:

```json
{
  "exporter": {
    "url": "$REACT_APP_OTEL_URL",
    "apiKey": "$REACT_APP_OTEL_KEY"
  }
}
```

Your `.env.local` file must be in `.gitignore`. The `telemetry.config.json` file
is safe to commit — it contains only `$VAR_NAME` references, never real values.
