## TelemetryProvider

The root component. Wrap your entire application with this.

```tsx
import { TelemetryProvider } from 'react-telemetry-open'
import appConfig from '../telemetry.config.json'

<TelemetryProvider appConfig={appConfig}>
  <App />
</TelemetryProvider>
```

### Props

**`appConfig?: unknown`**

Static configuration imported from `telemetry.config.json`. Generated by `npx react-telemetry-open init`. Evaluated once at mount — changes after mount are ignored.

**`config?: Partial<TelemetryConfig>`**

Runtime configuration override. Applied on top of `appConfig`. Useful for values only known at runtime — consent flags, sampling rates, feature toggles.

Both props are optional. Without either, the package runs with defaults and logs a setup warning in development.

## useTraceRender

Tracks render count and duration for a specific component.

```tsx
import { useTraceRender } from 'react-telemetry-open/renders'

function UserDashboard({ userId, theme }: Props) {
  useTraceRender('UserDashboard', { userId, theme })
  return <div>...</div>
}
```

### Parameters

**`componentName?: string`** — Name shown in telemetry. Defaults to `"Unknown"` if omitted — a dev warning fires once per session.

**`props?: Record<string, unknown>`** — Optional. Pass the component's props to enable render reason tracking. On every re-render, the hook diffs the current props against the previous render's props and emits which props changed as `changedProps`.

### Emits

`react.render.duration` metric on every render with:

| Attribute | Description |
|---|---|
| `component` | The `componentName` you passed |
| `renderCount` | How many times this component has rendered this session |
| `priority` | `urgent` (> 16.67ms) or `deferred` (≤ 16.67ms) |
| `changedProps` | Comma-separated prop names that changed — only when props passed |

### Notes

- Safe in React StrictMode — double renders within 50ms are deduplicated
- Uses `useLayoutEffect` for accurate timing, `useEffect` for emit
- Does not track which props changed unless you pass `props`

## useTrackInteraction

Tracks user clicks and inputs on a named element.

```tsx
import { useTrackInteraction } from 'react-telemetry-open/interactions'

function CheckoutButton() {
  const { onClick } = useTrackInteraction('checkout-submit')
  return <button onClick={onClick}>Buy Now</button>
}
```

### Parameters

**`elementName: string`** — Name shown in telemetry for this element.

### Returns

An object with event handlers to spread onto your element:

**`onClick: (e: React.MouseEvent) => void`** — Wrap your click handler with this.

**`onChange: (e: React.ChangeEvent) => void`** — Wrap your input change handler with this.

### Emits

`interaction.click` log on every click, `interaction.input` log on every input change with:

| Attribute | Description |
|---|---|
| `element` | The `elementName` you passed |
| `component` | Component where the hook is used |

### Notes

- Input values are never captured — only that an interaction occurred
- Rage clicks (3+ clicks in 500ms) are detected automatically on all elements without this hook

## useTrackEvent

Tracks custom business events.

```tsx
import { useTrackEvent } from 'react-telemetry-open/custom-events'

function OnboardingFlow() {
  const track = useTrackEvent()

  const handleStepComplete = (step: number) => {
    track('onboarding:step_completed', { step, plan: 'pro' })
  }
}
```

### Parameters

The returned `track` function accepts:

**`eventName: string`** — Name of the event. Use `category:action` convention for clarity.

**`properties?: Record<string, string | number | boolean>`** — Optional key-value pairs attached to the event. Values must be primitives. Total payload must be under 4KB.

### Emits

`custom.event` log with your `eventName` as the signal name and `properties` as attributes.

## useRouteTrace

Tracks route changes. Add once in your router component.

```tsx
import { useRouteTrace } from 'react-telemetry-open/routes'

function AppRouter() {
  useRouteTrace()
  return <Routes>...</Routes>
}
```

### Parameters

None.

### Emits

`route.change` span on every navigation with:

| Attribute | Description |
|---|---|
| `fromRoute` | Previous route pattern (e.g. `/users/:id`) |
| `toRoute` | New route pattern |
| `navigationDurationMs` | Time from click to render complete |

### Notes

- Works with React Router v6 out of the box
- For other routers, use `useTrackEvent` to track navigations manually

## Automatic signals

These fire without any hooks — just by wrapping your app in `TelemetryProvider`:

| Signal | Trigger |
|---|---|
| `js.error` | Any unhandled JavaScript exception |
| `js.unhandled_rejection` | Any unhandled promise rejection |
| `react.error` | Any React render crash caught by ErrorBoundary |
| `network.fetch` | Every `fetch()` call |
| `network.xhr` | Every XMLHttpRequest |
| `network.error_rate` | Ratio of failed requests, updated every 60s |
| `network.online` | Browser regains connectivity |
| `network.offline` | Browser loses connectivity |
| `browser.long_task.duration` | Any task blocking main thread over 50ms |
| `browser.memory.heap_used` | JS heap size, sampled every 30s |
| `web_vital.fcp` | First Contentful Paint |
| `web_vital.lcp` | Largest Contentful Paint (Chrome/Edge) |
| `web_vital.fid` | First Input Delay (Chrome/Edge) |
| `web_vital.cls` | Cumulative Layout Shift (Chrome/Edge) |
| `web_vital.inp` | Interaction to Next Paint (Chrome/Edge) |
| `interaction.rage_click` | 3+ clicks on same element within 500ms |
| `interaction.time_to_first` | Time from page load to first user interaction |
| `resource.load.duration` | Load time per JS/CSS/image/font asset |
